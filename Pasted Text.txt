La aplicación usa libcosmic, pero gran parte de la interfaz está construida manualmente con estilos, colores, emojis, barras y navegación propios. Funcionalmente sirve, pero visualmente se parece más a una aplicación Iced
  personalizada que a una aplicación COSMIC.

  ## Ajustes prioritarios

  ### 1. Usar la barra de título nativa

  Actualmente las acciones están dentro del contenido:

  - Navegador: “Abrir Carpeta” y breadcrumbs.
  - Visor: “Volver”, “Abrir Imagen”, zoom, recorte y guardado.

  Esto está en /home/pedro/Documentos/fotos/src/main.rs:582 y /home/pedro/Documentos/fotos/src/main.rs:760.

  Deberías implementar:

  - header_start() para volver al navegador.
  - header_end() para abrir, guardar, zoom y recorte.
  - set_header_title() para mostrar la carpeta o archivo actual.
  - Botones button::icon.
  - Iconos icon::from_name.
  - tooltip con descripción textual.

  Por ejemplo:

  - folder-open-symbolic
  - zoom-in-symbolic
  - zoom-out-symbolic
  - zoom-original-symbolic
  - edit-cut-symbolic
  - document-save-as-symbolic
  - go-previous-symbolic

  Evitaría una toolbar con nueve botones de texto. En ventanas angostas debería convertirse en un menú mediante responsive_menu_bar.

  ### 2. Reemplazar la sidebar manual por nav_bar

  La sidebar de ubicaciones se arma manualmente en /home/pedro/Documentos/fotos/src/main.rs:591 y /home/pedro/Documentos/fotos/src/main.rs:440.

  Conviene usar:

  cosmic::widget::nav_bar::Model

  Con entradas para:

  - Carpeta personal.
  - Imágenes.
  - Documentos.
  - Descargas.
  - Otras ubicaciones, si se agregan después.

  Esto proporciona automáticamente:

  - Selección activa.
  - Ancho y espaciado COSMIC.
  - Integración con el botón de navegación del header.
  - Modo condensado.
  - Comportamiento responsive.
  - Estilo consistente con COSMIC Files.

  Los emojis 🏠, 🖼️, 📄 y 📥 deberían reemplazarse por iconos simbólicos.

  ### 3. Eliminar colores RGB fijos

  Las tarjetas, carpetas y selección usan colores definidos manualmente en /home/pedro/Documentos/fotos/src/main.rs:285 y /home/pedro/Documentos/fotos/src/main.rs:393.

  Ejemplos problemáticos:

  Color::from_rgb(0.2, 0.6, 1.0)
  Color::from_rgba(1.0, 1.0, 1.0, 0.05)

  Eso rompe:

  - Tema oscuro.
  - Temas personalizados.
  - Alto contraste.
  - Color de acento elegido por el usuario.

  Los estilos deberían derivarse de:

  O, preferentemente, usar clases nativas de botones, contenedores, listas y segmented buttons sin definir colores manualmente.

  ### 4. Usar un grid responsive

  La cuadrícula está fijada a cuatro columnas en /home/pedro/Documentos/fotos/src/main.rs:660.

  Eso produce dos problemas:

  - La cantidad de columnas no responde al ancho.
  - La navegación con ↑ y ↓ asume siempre cuatro columnas en /home/pedro/Documentos/fotos/src/main.rs:950.

  Deberías usar widget::responsive junto con widget::grid para calcular:

  columnas = ancho_disponible / ancho_tarjeta

  El número real de columnas debe guardarse o calcularse también para la navegación por teclado.

  En una ventana angosta debería mostrar 2–3 columnas; en una pantalla grande, 5–8.

  ### 5. Simplificar las tarjetas

  Las tarjetas tienen varios contenedores anidados, bordes y tamaños rígidos de 130, 140 y 150 px.

  Para verse más COSMIC:

  - Miniatura con ContentFit::Cover o Contain.
  - Nombre debajo con elipsis.
  - Fondo transparente normalmente.
  - Fondo de acento únicamente en selección.
  - Radio y espaciado obtenidos del tema.
  - Un icono de carpeta nativo en lugar de una carpeta amarilla dibujada con rectángulos.
  - Skeleton o spinner nativo durante la carga, no el texto “Cargando...”.

  La previsualización de cuatro imágenes dentro de carpetas puede mantenerse, pero sobre una superficie neutra del tema.

  ## Visor de imágenes

  ### 7. Separar navegación, edición y metadatos

  La toolbar del visor mezcla:

  - Navegación.
  - Apertura.
  - Zoom.
  - Recorte.
  - Guardado.

  Una distribución más COSMIC sería:

  - Header izquierdo: volver.
  - Header central: nombre del archivo.
  - Header derecho: abrir, guardar y menú.
  - Barra inferior flotante o compacta: anterior, zoom, siguiente.
  - Context drawer: dimensiones, ruta, formato y otros metadatos.
  - Modo recorte: toolbar contextual que aparece solamente mientras se recorta.

  “Confirmar recorte” debería ser button::suggested; cancelar debería estar al lado.

  ### 8. El paneo declarado no funciona

  pan_offset y PanUpdate existen en /home/pedro/Documentos/fotos/src/main.rs:70 y /home/pedro/Documentos/fotos/src/main.rs:1206, pero el Canvas no publica movimientos de paneo cuando no está recortando.

  En /home/pedro/Documentos/fotos/src/main.rs:1300, el movimiento del cursor sólo hace algo dentro de:

  if self.is_cropping_mode

  Además, pan_offset nunca se utiliza al calcular la posición de dibujo.

  Hay que decidir entre:

  - Dejar que el scrollable gestione completamente el desplazamiento y eliminar pan_offset.
  - Implementar paneo real en Canvas y no depender del scrollable.

  Mantener ambos sistemas genera estados contradictorios.

  ### 9. Agregar modos de ajuste

  Sólo existe zoom incremental y 100 %. Para un visor COSMIC esperaría:

  - Ajustar a ventana.
  - Ajustar al ancho.
  - Tamaño real.
  - Zoom manual.
  - Recordar el modo entre imágenes.

  El modo inicial debería ser “Ajustar a ventana”, no siempre 100 %, porque una fotografía grande abre un Canvas enorme dentro del scrollable.

  ### 10. Barra de estado y metadatos

  ## Rendimiento y comportamiento

  ### 14. Evitar convertir cada imagen completa a PNG

  image_to_handle() vuelve a codificar cada imagen como PNG en /home/pedro/Documentos/fotos/src/main.rs:115.

  Para fotografías grandes esto implica:

  - Compresión PNG costosa.
  - Más uso de CPU.
  - Copias adicionales de memoria.
  - Retraso al cambiar de imagen.

  Es preferible construir el handle directamente desde RGBA si la API de la revisión fijada lo permite.

  ### 15. Limitar las tareas de miniaturas

  Al entrar a una carpeta se lanza una tarea por cada imagen y carpeta simultáneamente en /home/pedro/Documentos/fotos/src/main.rs:1042.

  En directorios grandes esto puede saturar:

  - CPU.
  - Disco.
  - Memoria.
  - Cola del executor.

  Conviene usar:

  - Cola con concurrencia limitada.
  - Caché de miniaturas en disco.
  - Cancelación mediante generación o ID de directorio.
  - Carga prioritaria de elementos visibles.

  La validación por índice y ruta evita aplicar miniaturas incorrectas, pero no evita trabajo innecesario después de cambiar de carpeta.

  ### 16. Reducir la caché del visor

  La caché guarda simultáneamente:

  DynamicImage + Handle

  para cinco imágenes en /home/pedro/Documentos/fotos/src/main.rs:62.

  Eso puede duplicar o triplicar la memoria. Cinco fotografías grandes pueden consumir cientos de MB.

  Conviene:

  - Mantener el DynamicImage sólo para la imagen editable actual.
  - Guardar handles de las imágenes vecinas.
  - Aplicar un límite por bytes, no sólo por cantidad.
  - Registrar tareas en curso para evitar precargas duplicadas.

  ### 17. Corregir soporte de formatos declarado

  Cargo habilita TIFF, pero is_image_file() y el diálogo no incluyen tif ni tiff.

  GIF se acepta, pero image::open() sólo produce una imagen estática; no hay reproducción animada.

  El README debería distinguir:

  - Formatos estáticos soportados.
  - GIF mostrado como primer frame.
  - Formatos realmente disponibles en navegador y diálogo.

  ### 18. Respetar eventos consumidos

  La suscripción global en /home/pedro/Documentos/fotos/src/main.rs:927 ignora el estado del evento.

  Debería procesar teclas sólo cuando:

  status == EventStatus::Ignored

  También conviene considerar:

  - repeat.
  - Modificadores.
  - Foco en menús y diálogos.
  - Atajos estándar como Ctrl+O, Ctrl+S, +, -, 0, Escape.
